# Phase 08.2: Close DOC-01 gaps (enforce required lint rules, gate release builds) - Research

**Researched:** 2026-10-31
**Domain:** ESLint 9 flat config enforcement, eslint-plugin-obsidianmd 0.3.0 internals, esbuild dead-code behaviour, GitHub Actions step gating
**Confidence:** HIGH. Almost every claim below comes from in-memory probes against the installed `node_modules` or from reading the installed rule source.

## Summary

Both blockers can be closed with config, script and workflow edits plus one small helper module. No new packages are needed. The probes found three facts that change how CONTEXT.md must be carried out:

1. **The preset never uses core `no-console`.** `eslint-plugin-obsidianmd` 0.3.0 sets `no-console: "off"`. Console checking actually happens inside `obsidianmd/rule-custom-message`, which runs its own private copy of `no-console` with `options: [{ allow: ["warn","error","debug"] }]`. It reports only when the original message matches a key in its `messages` map, so a message that matches no key is **silently dropped**. Every diagnostic is reported under the rule ID `obsidianmd/rule-custom-message`, and the text starts with `[no-console]`. As a result:
   - The right fix for D-01/D-04 is to override `obsidianmd/rule-custom-message` with `options: [{}]` and the message key `"Unexpected console statement."`. Do **not** turn on core `no-console`, because that gives two errors per call and the core message has no guidelines link.
   - The `debug.ts` exemption (D-02) must turn off `"obsidianmd/rule-custom-message"`. Setting `no-console: off` there does nothing.
   - **`options: []` fails open.** The wrapped core rule crashes on `context.options[0].allow`. The wrapper catches the error with `console.error` and every console call then passes lint. Probes confirmed this.
2. **A global `noInlineConfig` (or `--no-inline-config`) breaks the current tree.** `src/` has 36 legitimate `// eslint-disable-next-line obsidianmd/ui/sentence-case -- <reason>` comments in 6 files. With `noInlineConfig: true` the tree reports **36 errors and 36 warnings**. Moving those exceptions into rule options is out of scope and does not work cleanly anyway: setting `brands`/`acronyms` replaces the built-in defaults, and 35 errors remained. Recommended D-03 enforcement:
   - `linterOptions.reportUnusedDisableDirectives: "error"`
   - `--max-warnings=0`
   - a dependency-free **allow-list directive guard** (`lint:directives`), chained into `npm run lint`. It rejects every inline ESLint directive except `// eslint-disable-next-line obsidianmd/ui/sentence-case -- <reason>`.

   A rule-based guard (a local plugin rule) was also probed and **cannot** catch a file-level `/* eslint-disable */` or a self-disable, because those suppress the guard's own report.
3. **The release gate is just a step-order change.** GitHub applies a default `if: success()` to every step, and the default bash shell runs with `-e`. A failing `npm run lint` step therefore skips Build, Attest and Create release. A local simulation (described below) proved this against an edited copy of `release.yml`.

**Primary recommendation:** Commit in four stages, mechanical work first and docs last:
1. Add `src/utils/debug.ts` and migrate the 6 call sites.
2. Change `eslint.config.mjs`: wrapper override with `options: [{}]` and key `"Unexpected console statement."`, two rules set to `error`, `reportUnusedDisableDirectives: "error"`, and a `debug.ts` block turning off `obsidianmd/rule-custom-message`. Then change the `package.json` lint script to `eslint src/ --max-warnings=0 && npm run lint:directives`.
3. Split the `release.yml` Build step into `Install dependencies` → `Lint` → `Build plugin`.
4. Docs and bookkeeping.

"obsidianmd/rule-custom-message": [

    "no-console": {

        "Unexpected console statement.":

Core `no-console` stays `off`, as the preset sets it. This meets D-01's intent of rejecting all methods at error. ### Pattern 3: Inline-directive enforcement (D-03)

Global config block (add to the first, file-less block or a new block):
```js
linterOptions: { reportUnusedDisableDirectives: "error" },
```
The current effective value is `1` (warn) [VERIFIED: calculateConfigForFile]. With the wrapper design, `// eslint-disable-next-line no-console` targets a rule that never reports, so it becomes an **unused directive error**, and the console call itself still errors. Probe: `E 2: "Unused eslint-disable directive (no problems were reported from 'no-console')." + rule-custom-message`.

That alone does not stop `// eslint-disable-next-line obsidianmd/rule-custom-message`, `…prefer-active-doc`, blanket `// eslint-disable-next-line`, `/* eslint-disable */`, or `/* eslint obsidianmd/rule-custom-message: "off" */`. All of these suppressed the error in probes. So add the allow-list guard:

```json
"lint:directives": "! grep -rnE '(^|[^-[:alnum:]_])eslint([^.[:alnum:]_]|$)|/\\*[[:space:]]*(globals?|exported)([[:space:]*]|$)|^[[:space:]]*(globals?|exported)([[:space:]]|$)' src/ | grep -vE '^[^:]+:[0-9]+:[[:space:]]*// eslint-disable-next-line obsidianmd/ui/sentence-case -- [^[:space:]]'"
```
(This is the exact JSON string, generated with `JSON.stringify` and verified 2026-10-31, revision 2.)

Which comment shapes ESLint 9.39.4 honors (probed with `ESLint#lintText`, filePath `src/main.ts`, revision 2):
- Honored (rule turned off or downgraded): `/* eslint R: "off" */`; `/*` on one line and `eslint R: "off" */` on the next; `/* eslint` at end of line with the rule config on the next line; `/*\n  eslint R: "warn" */` (downgrade to warning); `/*\neslint-disable */`; `/* eslint-disable\nR */`; `/*\neslint-disable-next-line */`; trailing `/* eslint-disable-line */`; the same multi-line config shape for `obsidianmd/prefer-active-doc: 0`. ESLint trims the block-comment value, so the keyword may sit after any whitespace including newlines, and may be followed by a newline.
- Not honored: a continuation line that starts with `*` (`/*\n * eslint …`, `/**\neslint …`, `/** eslint … */`); line comments `// eslint-disable` and `// eslint R: "off"`; `/* eslint-env */` (ignored with a deprecation warning). `/* global document */` does not change `prefer-active-doc`.
- The first guard (`eslint-disable|/\*[[:space:]]*eslint[[:space:]]`) missed the two-line block config and the keyword-at-end-of-line config. Both silenced the console error (E 0 W 0).

How it works:
- The first grep lists every line in `src/` that contains the token `eslint` not preceded by a letter, digit, `_` or `-` and not followed by a letter, digit, `_` or `.`. This catches every directive keyword (`eslint`, `eslint-disable*`, `eslint-enable`, `eslint-env`) in any comment shape, on the `/*` line or on any continuation line, including the keyword at end of line. It does not match `@typescript-eslint/…` prose (2 lines in the real tree) or `eslint.config.mjs` references. It also lists `/* global …`, `/* globals …` and `/* exported …` config comments and continuation lines that start with those keywords. The real tree has none.
- The guard fails closed: a leading-`*` line such as ` * eslint x` is flagged even though ESLint ignores it. Prose in src/ must not use the bare word `eslint`.
- The second grep removes the one allowed form: a sentence-case-only next-line disable with a `-- reason`. It is anchored to the start of the line content (after grep's `path:line:` prefix, optional indentation), so a line that carries another directive before the allowed comment is still flagged (revision 2026-10-31, plan-checker finding).
- If anything remains, `!` turns grep -v's exit 0 into a failure, and the offending lines are printed.

Verified behaviour:
- Real tree → exit 0. All 36 existing directives match the allowed form.
- Temp fixture → exit 1. Flagged lines: `no-console`, `rule-custom-message -- r`, `/* eslint-disable */`, bare `// eslint-disable-next-line`, `/* eslint-disable local/x, obsidianmd/prefer-active-doc */`, `/* eslint obsidianmd/rule-custom-message: "off" */`, `// eslint-disable-next-line -- why`, `@typescript-eslint/no-explicit-any -- r`, `sentence-case, no-console -- r`, and sentence-case without a reason.
- Also flagged (anchored form, re-verified 2026-10-31): `const a = 1; /* eslint-disable */ // eslint-disable-next-line obsidianmd/ui/sentence-case -- x`.
- Also flagged (revision 2): line 2 of `/*` + `eslint obsidianmd/rule-custom-message: "off" */`; line 1 of `/* eslint` + `obsidianmd/prefer-active-doc: 0 */`; `/* global document */`.
- Not flagged: `// eslint-disable-next-line obsidianmd/ui/sentence-case -- acronym: ICS`. (also when indented), `// @typescript-eslint/no-misused-promises …`, `// see eslint.config.mjs`; the real tree still exits 0 (36 allowed directives, 2 `@typescript-eslint` prose lines not matched).

Why not `noInlineConfig`: on the real tree it produced 36 errors and 36 warnings (all 36 sentence-case exceptions in CalendarService.ts, SettingsTab.ts, viewRenderers.ts, CalendarView.ts, EmbeddedAgendaView.ts, EmbeddedCalendarView.ts). Supplying sentence-case `brands`/`acronyms`/`ignoreWords` options still left 35 errors, because the options replace the defaults and new violations appear, e.g. "URL", "Yaml". Note that with `noInlineConfig`, ESLint emits the warning `'// eslint-disable-next-line no-console' has no effect because you have 'noInlineConfig' setting in your config.` at fixed severity warning (linter.js:456), so it only fails with `--max-warnings=0`.

### Pattern 4: `src/utils/debug.ts` helper (D-02)

```ts
// Forensic-only developer logging. Flip DEBUG to true locally to see
// cache/fetch/timezone diagnostics; with false, the production build
// folds every wrapper to an empty function body.
// This is the only file exempt from the console rule (see eslint.config.mjs).
const DEBUG = false;

export function debugLog(...args: unknown[]): void {
  if (DEBUG) console.debug(...args);
}
export function debugWarn(...args: unknown[]): void {
  if (DEBUG) console.warn(...args);
}
export function debugError(...args: unknown[]): void {
  if (DEBUG) console.error(...args);
}
```
- **Do not write the literal text `eslint-disable` in this file's comments.** The directive guard greps for it.

### Anti-Patterns to Avoid
- **`options: []` in the wrapper override.** The wrapped core rule crashes and lint passes every console call. Probe: proposed log/debug/… = E0 with stderr `Error creating rule "no-console": TypeError: Cannot read properties of undefined (reading 'allow')`. stderr noise is the only sign.
- **`no-console: "off"` as the debug.ts exemption.** It does nothing, because the wrapper reports under `obsidianmd/rule-custom-message`.
- **Global `noInlineConfig` or `--no-inline-config`.** It breaks the 36 sentence-case exceptions.
- **A message key that is a substring of a message no-console never emits**, e.g. keeping the old "Only these console methods…" key with `options: [{}]`. Every report is dropped and lint fails open.
- **Writing "eslint-disable" in prose comments inside `src/`.** It trips the directive guard. This is intentional and fails closed.

## Common Pitfalls

### Pitfall 1: Wrapper fails open
**What goes wrong:** console calls stop being reported and lint is green.
**Why:** `options: []`, a crash inside the wrapper, or a message key that doesn't match the emitted text.
**How to avoid:** use `options: [{}]` and the key `"Unexpected console statement."`. Always run the five-method probe after editing.
**Warning signs:** `Error creating rule "no-console"` on stderr, or a probe showing E0.

### Pitfall 2: Inline-config switch breaks sentence-case
**What goes wrong:** 36 sentence-case errors suddenly appear.
**How to avoid:** use the grep guard instead (Pattern 3).

### Pitfall 3: Override ordering
**What goes wrong:** the debug.ts exemption is overridden by the later `src/**/*.ts` block.
**How to avoid:** put the debug.ts block after every `src/**/*.ts` block that sets `rule-custom-message`. Check with `calculateConfigForFile("src/utils/debug.ts")`, which should show `[0]`.

### Pitfall 4: `--max-warnings=0` makes any warn rule fatal
**Context:** that is intended (D-05). Preset `warn` rules that apply to `.ts` files include `no-self-compare` and sentence-case-json/locale variants. The tree is currently at 0 warnings, so nothing breaks today.

### Pitfall 5: Stale 08.1 structural check
Covered in Pattern 5. Record in VERIFICATION that it was superseded on purpose.

### Pitfall 6: Docs contradict the new policy
`CONVENTIONS.md:234-237` currently says "intentional, single-site exceptions use a per-line `eslint-disable-next-line <rule> -- <reason>` comment". `CONVENTIONS.md:334-336` advises inline `@typescript-eslint/no-explicit-any` disables. Both contradict D-03 and the guard. Lines 322-327 describe per-file `const DEBUG` guards. Update all three. The only inline form still permitted is `obsidianmd/ui/sentence-case` with a reason, for UI copy containing proper nouns or acronyms. That rule is not in the DOC-01 list. Document it as the single allowed inline form.

### Pitfall 7: Simulation must not run `npm ci` against a symlinked node_modules
`npm ci` deletes `node_modules`. In a temp copy with a symlink, it could wipe the real tree's dependencies. The simulation skips the `npm ci` step and only records it, because dependencies are already present.
