<objective>
Restore the BRAT beta channel and align the release workflow's toolchain with the lint gate, without disturbing the DIR-12 build-provenance attestation.

Purpose: The v1.15 milestone audit (flow f, PARTIAL) found that `release.yml` creates every release as a draft. BRAT cannot see drafts, so a beta tag such as `1.16.0-beta.1` never reaches testers. That breaks the project's beta-release flow. The same audit flagged the release job as still on checkout/setup-node v3, Node 18 and `npm install`, while `lint.yml` uses v4, Node 20/22 and `npm ci`.

Output: One modified file, `.github/workflows/release.yml`.

Planner decisions (no CONTEXT.md exists, so these are Claude's discretion and recorded here for traceability):
- PD-01: A tag that contains a hyphen (`*-*`, meaning a semver pre-release identifier) is released with `gh release create --prerelease` and NOT as a draft, so it is published at once and BRAT picks it up. Any other tag keeps today's behaviour: a draft that is published by hand. Classification happens in the shell on the quoted `$tag` variable.
- PD-02: Use `actions/checkout@v4` and `actions/setup-node@v4` with Node `20.x` (the lowest version in lint.yml's matrix), and install with `npm ci`. Unlike lint.yml, enable NO npm cache in the release job, because it mints signed provenance and must not restore dependency caches written by other runs. Keep major-tag pins (`@v4`) to stay consistent with lint.yml; SHA pinning is out of scope (see T-08.1-02). Leave the permissions block and the attestation step untouched.

Spec-less probe fallback: Phase 08.1 has no REQUIREMENTS.md IDs, so the edge probe was skipped (visible skip: nothing to probe). Prohibitions were recalled in-prompt and authored descriptor-less in `must_haves.prohibitions`.
Source audit: the full phase-level coverage audit and the deferred-item list are in `08.1-03-PLAN.md` (`<source_audit>` / `<deferred>`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git tag push → GitHub Actions runner | A tag name (attacker-influenced if someone with push rights or a compromised token pushes a crafted tag) flows into a shell script |
| GitHub Actions → third-party / GitHub-owned actions | `actions/checkout`, `actions/setup-node`, `actions/attest-build-provenance` code runs with a write-scoped GITHUB_TOKEN and an OIDC token |
| npm registry / Actions cache → release build | Dependencies installed into the job that produces the attested `main.js` |
| GitHub Releases → BRAT beta testers | A published prerelease is auto-installed by BRAT, which makes it a distribution channel |
