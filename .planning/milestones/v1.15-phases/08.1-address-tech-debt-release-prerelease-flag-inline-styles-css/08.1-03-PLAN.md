Planner decisions (no CONTEXT.md exists, so these are Claude's discretion and recorded here for traceability):
- PD-07 (ordering): GSD's verification staleness check (`findStaleVerificationSummary` in gsd-tools `verification.cjs`) treats a phase's VERIFICATION.md as stale when any SUMMARY in that phase changed strictly later. It uses commit time for clean committed files and mtime otherwise. Stale demotes the phase from complete and makes `roadmap update-plan-progress` refuse to tick it. So, per phase: edit the SUMMARY files first, edit the VERIFICATION.md last, and commit them in the same commit (equal commit time does not count as stale).
- PD-08 (dates): ROADMAP keeps real completion dates rather than today's date. Phase 5 is 2026-05-13, Phase 6 is 2026-05-14 (06-HUMAN-UAT.md), Phase 7 is 2026-05-16, Phase 8 is 2026-05-17. `roadmap update-plan-progress` keeps an existing ISO date in the Progress table but stamps today's date in the checklist bullet's `(completed …)` annotation, so that annotation is corrected afterwards.
- Plan 03 runs in wave 2 (after 01 and 02). Its addenda and CONVENTIONS text describe their results. Also, the execute-phase orchestrator itself writes ROADMAP.md and STATE.md after each plan, and serialising this plan avoids racing those writes.
