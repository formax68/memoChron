<objective>
Fix GitHub #61. When the default frontmatter (global or per-calendar) already declares `tags`, the event's calendar tags are merged into that property in place, so no second `tags` key is emitted (BUG-08). Merged tags are deduplicated, and every other frontmatter line, its order and the user's own tag values stay unchanged. When no `tags` key exists, the 1.15.0 append is kept byte-for-byte (BUG-09).

Purpose: Today a user whose default frontmatter has `tags:` gets a note with two `tags` keys. That is invalid YAML, so Obsidian's Properties panel errors or drops tags. The fix edits only the `tags` key's lines with a conservative line scanner, because a full YAML parse/re-serialize is Out of Scope. Any shape the scanner does not recognize is left untouched, never duplicated.

Output: `src/utils/frontmatterTags.ts` (new pure module), the `generateFrontmatter` integration in `src/services/NoteService.ts`, and tag fixtures added to the existing `verify-09.mjs` harness from Plan 09-01.

Decisions implemented: D-01, D-02, D-03, D-04, D-05, D-06, D-07, D-08, D-09, D-10 (from 09-CONTEXT.md).

Module-private consts:
- `TAGS_KEY_LINE` = the regex `^((["']?)tags\2[ \t]*:)(.*)$`. It matches a column-0 `tags` key, optionally wrapped in matching quotes. It does not match `tag:`, `Tags:` or indented keys (D-08).
- `NULL_VALUES` = a Set of `~`, `null`, `Null`, `NULL`, `""` and `''`.

Exported functions:
- `interface TagMergeResult { found: boolean; content: string }`. `found` means a top-level tags key exists, whether the frontmatter was merged, was already complete, or was left untouched as unsafe.
- `normalizeTag(tag)`: trim; strip one matching pair of surrounding double or single quotes; strip leading `#` characters; trim; lowercase (D-05).
- `splitComment(value)`: returns [body, comment]. A comment starts at a `#` that is at index 0 or preceded by whitespace, outside quotes. `body` is right-trimmed (D-10).
- `yamlSafeTag(tag, flow)`: returns the tag unchanged unless it would not be a valid plain scalar, in which case it returns `JSON.stringify(tag)`. A tag needs quoting when it starts with one of `- ? : , [ ] { } # & * ! | > ' " % @` or a backtick, or contains colon-space or whitespace-then-#, or (only when `flow` is true) contains a comma or a bracket/brace. Assumption A2.
- `mergeCalendarTags(frontmatter, calendarTags)`, step by step:
  1. Split on newline and find the lines matching `TAGS_KEY_LINE`. With 0 matches, return `{ found: false, content: frontmatter }` unchanged. With more than 1 match, return the untouched result `{ found: true, content: frontmatter }` (D-03).
  2. Split the key line into keyPart, the leading whitespace of the value, body and comment.
  3. The region is the following lines that are blank, comments, indented, or a column-0 `- ` item.
  4. A `pickNew(existing)` closure seeds a seen-set with the normalized user tags. It returns the calendar tags whose normalized form is non-empty and unseen, adding each to the set as it goes, so calendar tags are also deduped among themselves. Calendar tags keep their written casing (D-04, D-05, D-06).
  5. Block/empty branch, when body is empty or in `NULL_VALUES`:
     - Every non-blank, non-comment region line must be a dash item at one identical indent. Any other line returns untouched.
     - When there are no items, rewrite the key line to keyPart plus the comment suffix (this drops the null-ish value) and insert `  - {yamlSafeTag(tag, false)}` lines directly after it. That is exactly the formatTagsYaml item format.
     - When there are items, insert `{indent}- {yamlSafeTag(tag, false)}` lines directly after the LAST item line. Indentless column-0 lists are supported (Pitfall 3).
     - When there is nothing new, return untouched.
  6. TRACER SCOPE: in this task, every non-empty, non-null body (inline array, scalar, flow mapping, block scalar, ...) returns the untouched result. That is D-03-safe: never a second key, and calendar tags are skipped for those shapes until Task 2.
