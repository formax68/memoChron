## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| contributor source → lint gate | Any change under `src/` must pass `npm run lint` before CI and release accept it | Source code (policy enforcement, no secrets) |
| plugin runtime → user developer console | Logs written by the plugin are visible to users and other plugins | Diagnostic strings (may include calendar URLs / event data if logged) |
| git tag push → GitHub Actions release job | A tag triggers a signed, attested, published build | Tag ref, OIDC token, `GITHUB_TOKEN` |

## Findings

1. **All high-severity mitigations verified** (T-08.2-01, -02, -05, -SC), and the checks were re-run on 2026-10-31: the console/document probe, the directive allow-list fixture, `npm run lint` (exit 0), and greps on the release.yml gate order, cache keys and `github.ref` usage.
2. **Advisory (low, non-blocking): stale Logging guidance (T-08.2-10 residual).** `.planning/codebase/CONVENTIONS.md` `## Logging` and `CLAUDE.md` `## Logging` still recommend the raw `console` API. The planned DOCS_OK gate did not check these sections. Recommend rewriting both to point to `debugLog`/`debugWarn`/`debugError` and `Notice`. The source code was not changed by this audit.
3. **Accepted risks:** two risks were accepted at plan time (POSIX-only directive guard; live release gate not yet seen on a real tag).
4. **Summary threat flags:** none of the three SUMMARY files has a `## Threat Flags` section. 08.2-03-SUMMARY states that the phase added no new package, endpoint or trust boundary.
