Interpretation notes (recorded choices, from RESEARCH and the D-03 amendment):
- D-01 is enforced through the preset wrapper `obsidianmd/rule-custom-message`, which runs its own copy of core no-console. Core `no-console` stays `off` as the preset sets it, because enabling it too doubles every diagnostic and loses the guidelines link (RESEARCH Pattern 1, assumption A2).
- D-02's "`no-console: off` override" for debug.ts is implemented as `"obsidianmd/rule-custom-message": "off"` in a debug.ts-only block. A plain `no-console: off` would do nothing, because the wrapper reports under its own rule ID (RESEARCH Anti-Patterns). The intent is kept: one exempt file, one commented block.
- D-03 is enforced with `reportUnusedDisableDirectives: "error"`, `--max-warnings=0` and an allow-list guard. A blanket `noInlineConfig` is not used (D-03 amendment, chosen by the user).
- Ordering pitfall: the tightened config flags the six existing debug sites, so Task 1 migrates them in the same commit that adds the console override.
- Residual scope, not addressed here: `prefer-active-doc` checks only `document`. Bare `window` use is not linted by any rule. Adding a rule is outside the phase boundary ("no new lint rules"), so this is recorded as deferred in plan 03.
- Spec-less probe fallback skipped: the phase had no requirement IDs in ROADMAP when planning started, and no SPEC.md exists (visible skip). The audit's B1/B2 close criteria and the D-10/D-11 probe sets are the acceptance bar.
