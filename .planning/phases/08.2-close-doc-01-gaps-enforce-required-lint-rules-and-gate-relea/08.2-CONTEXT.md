<domain>
## Phase Boundary

Close milestone-audit blockers **B1** and **B2** so DOC-01 is genuinely satisfied before v1.15 archival:

- **B1:** The tag-triggered release workflow must not build, attest, or publish when lint fails.
- **B2:** Every DOC-01-required violation must make `npm run lint` exit non-zero. This includes ungated `console.debug/warn/error` and bare-`document` popout violations, which pass or only warn today. The only allowed exception is the documented developer-debug path.

Out of boundary: new lint rules beyond the DOC-01 list, linting files outside `src/`, persistent test suites, any source behavior change beyond moving the six debug-gated log calls behind a shared helper.

<decisions>
## Implementation Decisions

### Console rule + DEBUG exceptions (B2)
- **D-01:** `no-console` rejects **all** console methods at `error` severity (no `allow` list). This overrides the obsidianmd preset's `allow: [warn, error, debug]`.
- **D-02:** Create a shared `src/utils/debug.ts` that owns the single `const DEBUG = false` and thin wrappers (e.g. `debugLog` / `debugWarn` / `debugError`; the planner picks exact names). Migrate the six existing `if (DEBUG) console.*` sites in `src/services/CalendarService.ts` (lines ~17, 302, 387, 405, 455) and `src/utils/timezoneUtils.ts` (lines ~7, 211, 220) to the helper and remove their per-file `DEBUG` constants. Only `src/utils/debug.ts` gets a `no-console: off` override, as one config block with a comment explaining why. Call sites contain no `console` references.
- **D-03:** Forbid inline `eslint-disable` for scorecard rules **and enforce it**: set `linterOptions.reportUnusedDisableDirectives: "error"` and stop inline config from bypassing rules (`--no-inline-config` in the lint script, `linterOptions.noInlineConfig: true`, or an equivalent the researcher confirms works with ESLint 9 flat config). Update `.planning/codebase/CONVENTIONS.md:236` (Directory Compliance intro) to say that exceptions go in `eslint.config.mjs` or the debug helper, never in inline disables. Also update the DIR-01 Don't/Do block (~line 322) so it points to `src/utils/debug.ts` instead of per-file `const DEBUG` guards.
- **D-04:** Keep the obsidianmd `rule-custom-message` guidelines link for console violations. Update its mapping so the message key matches what the new `no-console` config emits (with no allow list the ESLint message text changes). The preset currently keys off "Only these console methods are allowed: warn, error, debug.". Verify that a probe shows the custom message.

### Warning-level rules (B2)
- **D-05:** Do **both**: set `obsidianmd/prefer-active-doc` and `obsidianmd/prefer-file-manager-trash-file` to `error` in `eslint.config.mjs`, AND add `--max-warnings=0` to `npm run lint`. The current tree has 0 errors and 0 warnings, verified 2026-10-31 with `npx eslint src/ --max-warnings=0` (exit 0).
- **D-06:** Lint scope stays `src/` only. Do not expand to `eslint .` or manifest validation in this phase.

### Release gate shape (B1)
- **D-07:** Add an `npm run lint` step to the existing `build` job in `.github/workflows/release.yml`, after `npm ci` and before `npm run build`. A failure stops the job before the attest and `gh release create` steps run. Do not add a separate job or a `workflow_call` refactor, and do not change the npm `build` script.
- **D-08:** The release lint runs on Node 20.x only, the same version as the release build. Keep the uncached install on the attested path (08.1 decision). Keep hyphenated-tag non-draft prerelease and stable draft routing unchanged.
- **D-09:** `lint.yml` stays as is. It picks up the stricter rules automatically through `npm run lint`.

### Proof + bookkeeping
- **D-10:** B2 proof uses **recorded in-memory ESLint probes** (`ESLint#lintText` with `filePath: "src/main.ts"`), with results recorded in VERIFICATION.md. No saved test or probe files (no-new-tests constraint). Minimum probe set:
  - `console.log`, `console.debug`, `console.warn`, `console.error`, `console.info`: each is an error
  - bare `document.` access that `prefer-active-doc` catches: error
  - an inline `// eslint-disable-next-line no-console` above a console call: still fails
  - a call through the debug helper: passes
  - the real tree: `npm run lint` and `npm run build` both exit 0
- **D-11:** B1 proof is a **YAML step-order trace plus local simulation**: show that `npm run lint` comes before build, attest and release in `release.yml`, and that a non-zero lint exit stops the same command sequence locally. **No throwaway tag pushes.** The next real beta tag, pushed by the user, is the live confirmation and is recorded as pending human verification.
- **D-12:** **Reassign DOC-01 to Phase 08.2.** In `.planning/REQUIREMENTS.md`, uncheck DOC-01 and change its traceability from Phase 5 to Phase 08.2 (status Pending until verification passes). Set ROADMAP Phase 08.2 `Requirements: DOC-01` and fill in its Goal/Success Criteria. Add a dated reopening note in Phase 05's records (e.g. a 05-VERIFICATION addendum) that cites the v1.15 audit B1/B2. Check DOC-01 again only after 08.2 verification passes.

### the agent's Discretion
- Exact helper names and signatures in `src/utils/debug.ts`, provided the call sites have no `console` references and `DEBUG = false` keeps production silent. Prefer a shape where the bundler can drop the calls or makes them cheap no-ops.
- Which inline-config enforcement mechanism to use for D-03 (CLI flag or `linterOptions`), whichever ESLint 9.39 supports best.
- Commit ordering. Suggested: debug helper and site migration → eslint config/script tightening → release.yml gate → docs/bookkeeping, mirroring the earlier "mechanical first, docs last" phases.
- Any wording updates to `CLAUDE.md`'s Directory Compliance pointer, if it repeats the inline-disable guidance.

</decisions>
